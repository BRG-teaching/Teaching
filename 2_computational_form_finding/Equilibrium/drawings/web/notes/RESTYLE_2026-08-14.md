# Restyle study — reference video vs our 53 views (2026-08-14)

Source: user-provided screen recording (30 s, 1306×720) of a truss form-finding
walkthrough app ("GIVEN — 6-PANEL TRUSS", 36 steps, Rhino .3dm export panel).
Frames extracted at 1 fps; colors sampled per-pixel. Compared against fresh
final-step screenshots of our views 1, 8, 24, 36.

## 1. The video's design language (measured)

### Palette (pixel-sampled)
| role                          | video value                | our current value |
|-------------------------------|----------------------------|-------------------|
| canvas background             | #fdfdfd–#ffffff            | same (white) |
| context / site                | hairline grey ~#b0b0b0     | grey, but heavier weight |
| lines of action / guides      | dotted light grey          | dashed grey (ok) |
| loads + reactions             | green ~#3f9c20, THIN       | green #51923d, thick arrows |
| compression                   | deep navy ~#1414b4         | bright blue #2563eb |
| tension                       | dark brick red ~#8f1a1a    | pink #ce4095 |
| current-step action           | pink ~#c04080              | black #111 (flash), pink points |
| used construction rays        | pale teal dashed ~#85b3b3  | grey (uniform with guides) |
| drag handles                  | pink dots #c85898          | white disks (no affordance) |
| trial funicular               | grey, persists             | same ✔ |
| sidebar                       | #080b12, pink accents      | #16181d, pink accents ✔ |

Key observation: pink has exactly ONE meaning in the video — "this is what is
happening right now" (current segment, current ray, handles, UI accent).
The *resolved* drawing is calm: navy / brick / black numbers / grey context /
thin green. Nothing in the final state is pink.

### Line-weight discipline
Everything is hairline. Load arrows are short and thin with small labels
ABOVE them. Member numbers tiny, black, monospace. Node letters tiny grey.
At the final INTERNAL FORCES step, member stroke widths become ∝ |force|
directly — no translucent halo pipes. Max ~4–5 px at 720p.

### The caption card (top-left, the single strongest device)
White card, soft shadow, monospace:
```
INTERNAL FORCES                          step 36/36   ← bold caps + pink step
member widths ∝ |force| · red = tension, blue = …     ← 1–3 detail lines
max compression -4.00 kN · max tension 5.09 kN        ←   with LIVE numbers
top chord: 4.00 · 4.00 · 4.00 · 4.00 · 4.00 · 4.00 kN
uniform load: every top-chord panel carries exactly F ← pink takeaway line
```
Every step carries computed values (node coords "L = (3.14, 5.09)",
"R1 (left) = LL0→H = 2.50 kN", member force + COMPRESSION/TENSION/zero-force
verdict). The takeaway line states the *insight*, not the construction.

### Annotations near geometry, not side lists
Reactions appear as thin green double-arrow brackets ON the load line labeled
`R1=2.50` / `R2=2.50`. Constant force noted `F = 4.0` above the rays. No
separate colored value column floating beside the diagram.

### Past vs present encoding in the force diagram
Rays already used stay visible as thin pale-teal dashed; the ray being used
right now is pink; the finished members overlay navy/brick. Reading the force
diagram you always see: past = teal, now = pink, done = final color.

## 2. Gap analysis — what makes ours look less modern

Ranked by visual impact (worst first):

1. **Pink soup in final states.** Tension pink + translucent pink pipe halos
   + pink numeric side lists + pink UI: views 8/24 read as 70% pink. The
   video's endstate has zero pink. Pink must mean "now", not "tension".
2. **Saturated heavy strokes.** Our #2563eb is bright; force-diagram green
   reaction chains are thick wedges (view 8); pipes are wide translucent
   smears. Video: thin navy/brick lines, magnitude shown by width only at
   the final step. This is most of the "red-greenish" garishness the user
   sees — bright pink-red + olive green side by side at heavy weight.
3. **One-line caption vs rich card.** Ours states the move; the video's card
   teaches: title, live numbers, and a highlighted takeaway. We already
   compute every number (regressions prove it) — we just never show them
   in the caption.
4. **Values as colored side lists** (views 8/24/36) instead of near-geometry
   brackets + caption values. The colored lists (pink/blue/green text blocks)
   add to the color noise.
5. **No past/present encoding** — all our construction rays are the same
   grey whether long-used or just drawn.
6. **No drag affordance** — draggable points look like every other node.
   The video's pink handles instantly communicate interactivity.
7. **Label typography** — ours are larger and colored like their elements;
   video labels are small, monospace, mostly grey/black; color is reserved
   for the geometry itself.

Already matching (keep): white canvas, dark sidebar + pink UI accent, grey
persistent trial, dashed closing lines, form/force paired steps, step
progress bar, autoplay, node lettering + member numbering in both diagrams.

## 3. Proposed plan (phased; every phase = lib-level so all 53 views inherit)

### Phase A — palette regrade (PAL in eqdraw.js + label styles)
- compression #2563eb → deep navy **#1a1eb2**
- tension #ce4095 → brick crimson **#9e2020** (pink becomes current/UI only)
- loads/reactions green → **#3f9c20**, arrow shafts/heads thinned ~40%,
  offset reaction chains thinned to load-symbol weight
- guides/context lightened one step; labels: smaller, monospace, grey-first
  (element-colored only for member numbers)
- current-step flash stays pink family (#ce4095) — this now matches the
  video exactly (black flash retired, pending→pink like handles)
- ghost teal stays (it is already the video's teal family)
Then re-render ALL 53 movies (standing rule after palette change).

### Phase B — caption card upgrade
- lib: caption renders as top-left card: bold caps TITLE + pink `step k/N`,
  monospace detail lines, optional pink `takeaway` line.
- step API gains `{title, detail:[], takeaway}`; legacy single-string
  captions render unchanged (title only) so all views keep working; views
  retrofitted incrementally with live numbers (they already compute them).

### Phase C — final internal-forces presentation
- replace translucent pipe halos with **member stroke width ∝ |force|** at
  the resolve step (o1 toggle keeps its semantics: on = width-graded,
  off = uniform thin). Calm navy/brick final state like the video.

### Phase D — construction past/present + affordances
- used force-diagram rays/parallels: thin dashed pale teal (one step darker
  than ghost so they don't collide); current ray: pink.
- draggable points: small pink fill (video handle #c85898), hover ring +
  grab cursor.

### Phase E — near-geometry annotations
- reaction double-arrow brackets with live values on the load line
  (`R1=2.50`) where views have reactions;
- migrate the colored side value-lists into caption detail lines / small
  grey annotations at the geometry.

### Verification per phase
Per-step screenshot grid over a 6-view sample (1, 8, 18, 24, 36, 44) →
full sweep, ghost_audit.py on ghost-completed views, movies re-render,
push (= deploy), reload user's gallery tab.

## 4. Decisions (user, 2026-08-14) + implementation status

1. **Tension color: PINK STAYS** ("for forces themselves I liked the pink
   color rather than red"). Brick red was tried and reverted the same day.
   Final palette: navy #1a1eb2 compression, pink #ce4095 tension, green
   #3f9c20 loads, black current-step flash (as before), grey #aaaaaa guides.
2. **Pipes: width ∝ force** — DONE. All 44 pipe views: the translucent halo
   quads are now OPAQUE (opacity 1.0, z −0.18, above region fills, below
   guides/members), and PIPE_SCALE = 0.5 inside V.rectPoints halves the old
   halo widths — pipes read as the member itself thickened, like the video.
   rectPoints is pipe-only (verified across all call sites); view 44's
   N/V/M plots use separate sND/sVD/sMD scales and are untouched.
3. **Caption card: top-left** — DONE (lib + CSS). Step entries accept
   `detail` (array of monospace lines) and `take` (pink takeaway line);
   both may be functions (d, state) => value for live numbers. Retrofitted
   with live values so far: views 1, 8, 12, 24, 36 — the remaining 48 views
   render the card with title + main line and can gain detail/take
   incrementally.
4. **LINE_SCALE = 0.72** (eqdraw.js) thins every stroke, arrowhead and
   dashed arrow lib-wide.
5. **Drag handles** — DONE lib-only: any disk whose center the view's drag
   hit-function claims (probed with 1e-9 tolerance on every applyStep)
   renders as a solid pink dot (face #ce4095, edge #a83179), overridden by
   hover/flash/selection. Zero per-view changes; step-windowed hits mean
   handles light up only when actually draggable.
6. **Teal "used ray" encoding: NOT adopted** — it would contradict the
   standing applet-fidelity rule (construction rays are grey where the live
   applets draw them grey). The ghost preview already owns teal = future.
